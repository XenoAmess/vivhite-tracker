# 项目产品与技术评审（2026-08-14）

> 评审范围：产品价值 / 技术债 / 开发效率 / 竞争力 / 扩展性。
> 不含安全合规。基线版本 v1.13.0（commit 9a6ce05），数据均为实测。

## 1. 项目现状总结

**产品定位**：B 站主播「白绮」的单人直播监控 + 观播手账工具（牢白播了吗）。
单模块 Kotlin App（88 个文件 / ~14k 行主代码），minSdk 26 / target 36。

**核心链路**（全部闭环且测试覆盖）：
- 监控：AlarmManager 60s 轮询 + WorkManager 兜底 + 四 Receiver 重启链 + Doze/ROM 缓解
- 提醒：开播响铃（勿扰/观播静音/主题变化/动态流四类提醒）
- 手账（绮迹手账）：场次自动记录 + 心情事件（22 种心情/时长联动）+ 魔法期标记 +
  人气曲线 + 粉丝快照 + 统计弹窗（月趋势/时段热力/词云）+ 搜索 + 批量管理 +
  CSV 导入导出 + 月度海报 + 自动备份（SAF）+ 月初自动海报
- 更新：stable/beta 双通道 + ApkDiffPatch 增量补丁 + 镜像加速 + 302 免 API 回退

**工程指标**（实测）：

## 2. 主要问题列表

1. **单用户硬绑定**：房间号/UID 虽收敛到 `BiliTargets`，但通知文案、海报文案、
   手账语义全是「白绮」写死——改目标要全局搜文案。产品形态决定这不是债，但
   **若要分发给别人用**就是硬门槛（黑名单已否决多主播，记录备查）。
2. **手账页信息密度逼近极限**：摘要卡 + 五操作按钮 + 柱图 + 日历 + 场次列表 +
  心情区，单屏 6 个功能块；拆 Tab 已被否决，需要靠**默认折叠/渐进展示**缓解。
3. **心情记录无入口引导**：功能强但藏得深（要点日期 → 添加），新用户发现率堪忧。
   下播心情快捷记录已被否决，更需一个轻量引导。
4. **海报/手账内容型功能依赖人工目检**：golden 测试是结构级（签名色），
   文案错位/溢出这类问题只能靠模拟器截图人工看。
5. **后台保活依赖用户手动操作**：电池白名单/自启动引导已做，但国产 ROM 上
   仍可能断链——这是平台限制，代码只能缓解（已有文档）。

## 3. 优化机会列表

1. **手账页渐进展示**：操作按钮区（搜索/统计/导出/导入/图片/管理）收成
   「更多」菜单，默认只留 1-2 个高频入口 —— 直接回应问题 2，不动信息架构。
2. **心情首启引导**：首次进手账页且心情为空时，高亮「＋添加」一次性提示
   （SharedPreferences 一次性标记）。
3. **检测循环可观测闭环**：健康度页已展示间隔/成功率，可加「最近异常时间点」
   链接到日志页，形成自查 → 日志的闭环。
4. **CI 再提速**：instrumented job 与 build 共享 Gradle 缓存已做；下一步可把
   assembleRelease 挪到 release workflow 独占（CI push 只跑 debug），省 1-2 min。
5. **模拟器快照加速**：本地自测 `default_boot` 快照加载 ~3.6s 已可接受；CI 的
   android-test job 可开 AVD 快照缓存（reactivecircus 支持），省 30-60s。

## 4. 功能补全建议

> 已规避 `docs/feature-blacklist.md`（20 项否决不再提）。

1. **手账页「更多」菜单收纳**（体验，对应优化 1）
2. **心情记录首启引导**（体验，对应问题 3）
3. **健康度 → 日志页联动**（体验，对应优化 3）
4. **手账按周视图**：日历下方加「本周汇总条」（时长/心情 top1/魔法期天数），
   比月维度更贴近当下
5. **开播时手账自动预填心情**：开播瞬间心情往往强烈，下播后补记时把开播时间点
   默认带出（只预填时间，不自动选心情，不违反黑名单）

## 5. 技术优化建议

1. **CI job 拆分瘦身**：`android-test` 与 `build` 并行已好；把 assembleRelease
   从 CI 移除（release workflow 才需要），build job 省 1-2 min。
2. **Baseline Profile 重启条件**：AGENTS.md 已记录三道坎；等
   androidx.baselineprofile 支持 AGP 9 内置 Kotlin 后接入，预期冷启动 -10~20%。
3. **手账页长列表性能**：场次/心情双 RecyclerView nestedScrolling 在全量数据下
   会全量测量——分页已按月做（日历层），列表层可考虑 `RecyclerView` 固定高度
   + 内滚动，或 DiffUtil 替换 notifyDataSetChanged。
4. **Weekly 提醒周报**：BackupWorker 已验证 SAF 可行性，同理可加「手账周备份」
   Worker（当前备份周期 7 天已是该频率，不重复）。
